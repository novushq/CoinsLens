# C-2: Identification result card

- **Kind:** feature
- **Module:** `result`
- **Owns paths:** `feature/result/**`, `app/src/main/kotlin/app/novushq/coinlens/MainActivity.kt`, `app/src/main/kotlin/app/novushq/coinlens/di/AppModule.kt`

## Description

Screen for route `Result(scanId)`. If `scanId == null`, read `ScanDraft` and call `IdentifyCoinUseCase`; otherwise load the stored `ScanRecord`.
- Loading: skeleton of the result card with rotating hints ("Reading the date…", "Checking mint marks…").
- Success: museum-label card — `CoinFrame` (flip obverse/reverse), serif name, metadata row COUNTRY · YEAR · MINT MARK, composition/weight/diameter rows when present, rarity chip, `ValueRangeBar` with circulated and uncirculated ranges and `ConfidencePill`, `DisclaimerText` always visible below the value, error/variety hints as `PossibleHintChip` (text always starts with "Possible") with an expandable "where to look", alternatives list ("Could also be…").
- `recognized == false`: friendly not-a-coin state with Retake.
- Errors from `AppError` (network, quota, safety, parse) with Retry (retry does not consume allowance twice; only success consumes).
- Actions: **Add to collection** bottom sheet (choose/create folder, grade, purchase price, notes → `AddToCollectionUseCase`), **Share** → `Share(scanId)`, **Scan another** → Capture.
- No ads anywhere on this screen.

Only edit files under `feature/result/**`. Replace the core-provided stubs in `ResultEntry.kt` (`resultGraph` and `resultModule`); do not touch `:app`, `:core:*` or other features. Use designsystem tokens only, all four UI states via `UiStateSurface`, strings in `feature/result/src/main/res/values/strings.xml`, ViewModel exposes immutable `StateFlow<UiState>` + `onAction`, unit tests for the ViewModel with fakes and `kotlinx-coroutines-test`. Compose previews for each state.

## Acceptance criteria

- [ ] Identifying a draft with FakeIdentifyEngine shows the result card with name, country, year, mint mark, composition and rarity
- [ ] Circulated and uncirculated ranges render on one ValueRangeBar with a confidence label and the disclaimer always visible
- [ ] Every variety hint is rendered prefixed with 'Possible' and never as a certainty
- [ ] An unrecognized result and each AppError type render distinct states, and Retry does not consume a second scan
- [ ] Add to collection saves a CollectionItem with folder, grade, purchase price and notes
- [ ] ViewModel unit tests cover loading → success, unrecognized, error → retry

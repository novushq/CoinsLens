# C-1: Camera capture with coin guide

- **Kind:** feature
- **Module:** `capture`
- **Owns paths:** `feature/capture/**`, `app/src/main/kotlin/app/novushq/coinlens/MainActivity.kt`, `app/src/main/kotlin/app/novushq/coinlens/di/AppModule.kt`

## Description

CameraX (`camera-camera2`, `camera-lifecycle`, `camera-compose` `CameraXViewfinder`, version 1.6.2) capture screen for route `Capture`.
- Two steps: **Front** then **Back** (Back skippable). Circular guide overlay sized to 72% of the short edge with the label for the current side; `ImageCapture` takes the photo, then crop to the guide circle's bounding square and downscale to ≤1600px, JPEG q85.
- **Glare warning**: analyse the preview with `ImageAnalysis` (Y plane): if >6% of pixels inside the guide are ≥ 245 luma show "Glare detected — tilt the coin or move away from the light"; **blur warning** via variance of Laplacian below a threshold. Warnings are advisory, never block.
- Gallery import via Photo Picker (`PickVisualMedia`) as an alternative to the camera.
- Permission: rationale screen with a Grant button; permanently denied → open app settings.
- Before opening the camera check `ObserveScanAllowanceUseCase`; if `!canScan` navigate to `Paywall(source="quota")`.
- On done: write bytes into `ScanDraft` (core) and `navigator.navigate(Result(scanId = null))`.
- Put glare/blur math in pure functions with unit tests (synthetic luma arrays).

Only edit files under `feature/capture/**`. Replace the core-provided stubs in `CaptureEntry.kt` (`captureGraph` and `captureModule`); do not touch `:app`, `:core:*` or other features. Use designsystem tokens only, all four UI states via `UiStateSurface`, strings in `feature/capture/src/main/res/values/strings.xml`, ViewModel exposes immutable `StateFlow<UiState>` + `onAction`, unit tests for the ViewModel with fakes and `kotlinx-coroutines-test`. Compose previews for each state.

## Acceptance criteria

- [ ] Capture flow takes a front photo and optionally a back photo, cropped to the circular guide and ≤1600px, and stores both in ScanDraft
- [ ] Glare and blur detectors are pure functions with unit tests covering bright, normal and blurry synthetic inputs
- [ ] A glare warning banner appears while the guide area is over-exposed and does not block the shutter
- [ ] Gallery import via Photo Picker produces the same ScanDraft as the camera path
- [ ] When the scan allowance is exhausted the screen routes to Paywall(source=quota) instead of opening the camera
- [ ] Camera permission denied and permanently denied states render with a clear next action

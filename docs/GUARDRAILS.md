# CoinLens — Engineering guardrails

Generated by the factory. These rules are enforced by gates, not by judgement.
An agent that believes a rule is wrong must raise an ADR, not work around it.

| ID | Rule | Why | Enforced by |
|---|---|---|---|
| `LANG-001` | Kotlin only | One language across every module keeps the shared library and skills applicable everywhere. | review |
| `DI-001` | Koin is the only DI framework | A single DI style means shared snippets drop in unchanged and agents never argue about Hilt vs Koin. | static |
| `MOD-001` | Business logic lives in pure Kotlin modules | :core:model/:core:common/:core:domain must not import Android, so the logic is fast to test and impossible to couple to the UI. | static |
| `MOD-002` | Features never depend on other features | Feature isolation is what lets several agents work in parallel worktrees without merge conflicts. | static |
| `MOD-003` | Every new feature is its own `:feature:<key>` module | Module boundaries map 1:1 to task ownership. | review |
| `CO-001` | No GlobalScope | Structured concurrency: work must be cancelled with its owner. | static |
| `CO-002` | No runBlocking in production code | Blocking a thread to await a coroutine causes ANRs. | static |
| `CO-003` | Dispatchers are injected, never referenced directly | Tests need to substitute a TestDispatcher; hard-coded Dispatchers.IO makes suspending code untestable. | static |
| `ERR-001` | No silent catch blocks | Every failure becomes an AppError the UI can render. | static |
| `ERR-002` | Repositories return AppResult, they do not throw | One error envelope across layers keeps state handling uniform. | review |
| `VM-001` | ViewModels expose immutable state | A public MutableStateFlow lets the UI mutate state behind the ViewModel's back. | static |
| `VM-002` | ViewModels hold no Android Context or View | Holding a Context in a ViewModel leaks the Activity across config changes. | static |
| `VM-003` | Screen state is a single UiState value | One state object prevents impossible intermediate combinations. | review |
| `LOG-001` | No println | Logging goes through the injected Logger so release builds stay quiet. | static |
| `LOG-002` | No direct android.util.Log | Same reason; also keeps :core platform free. | static |
| `KT-001` | Avoid `!!` | Non-null assertions are crashes waiting for a bad backend response. | static |
| `TEST-001` | Core logic has unit tests | Business logic in pure modules is cheap to test; untested logic blocks merge. | build |
| `BUILD-001` | assembleDebug and test must pass before merge | A branch that does not build cannot be integrated. | build |
| `PERF-001` | Startup work stays off the main thread | Cold start is the most visible quality signal on the Play Store. | review |
| `UI-001` | No colour literals outside the design system | One scheme, defined once, is what makes an app look designed rather than assembled. | static |
| `UI-002` | No magic dimensions | A spacing scale is the difference between a tidy screen and a nearly tidy one. | static |
| `UI-003` | User-facing text comes from string resources | Localisation and copy review are impossible once text is inlined. | static |
| `UI-004` | Lazy lists declare stable keys | Without keys, scroll position and item state jump whenever the list changes. | static |
| `UI-005` | Composables accept a defaulted Modifier | A composable that cannot be sized by its caller forces wrapper layouts everywhere it is used. | static |
| `UI-006` | Collect flows with lifecycle awareness | collectAsState keeps working while the app is backgrounded and drains battery. | static |
| `UI-007` | Every screen renders loading, empty, error and success | A blank screen on failure is the most common one-star review. | review |
| `A11Y-001` | Icon-only controls carry a content description | Without it the control does not exist for a screen-reader user. | review |
| `SEC-001` | No app-wide cleartext traffic | It exposes user data and fails Play's security review. | static |
| `SEC-003` | Components declare android:exported explicitly | An accidentally exported component is an attack surface, and the build fails on API 31+ without it. | static |
| `SEC-005` | No credentials in source or build files | Anything in an APK is public. Keys come from gradle properties. | static |
| `DATA-001` | No destructive Room migrations | It silently deletes the user's data on upgrade. | static |
| `BUILD-002` | Release builds are minified and shrunk | Unminified releases are larger, slower to install and easier to reverse engineer. | static |
| `REUSE-001` | Check the shared library before writing infrastructure | Koin setup, networking, persistence, Result plumbing and test helpers already exist and are vetted. | review |
| `DOC-001` | Divergence from the PRD requires an ADR and a doc update | Documentation is the source of truth an agent loads months later. | review |
